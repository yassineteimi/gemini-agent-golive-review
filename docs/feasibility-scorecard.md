# Feasibility scorecard

!!! warning "Work in progress, phase 0 of 4. Not yet run against Gemini."
    This is a draft written from documentation and offline runs. Every status reads "to assess" until a phase produces evidence.

A bank's risk, compliance and IT teams ask the same handful of questions before an AI agent reaches staff. This page lists them for Banque Ardoise, says how this project will answer each one, and in which phase. A status changes only when there's evidence to link: a test, a log, a source.

| Criterion | Why the bank cares | How this project tests it | Phase | Status |
|---|---|---|---|---|
| Identity and single sign-on | Staff already sign in once to the bank's systems, and the access policy says an agent never sees more than the person asking. An agent with its own broad service account would break that rule. | Sign-in through Keycloak over OIDC; the user's token travels to the MCP server; a test checks that a branch adviser asking about an HR file gets a refusal, not an answer. | 1 | to assess |
| Document connectors | Procedures live in the bank's document systems with their permissions attached. Copying them into a new index means a second set of permissions to keep in sync. | An MCP server in front of the document store, compared with Gemini Enterprise's own connectors on permission handling and setup effort (ADR 0003). | 1 | to assess |
| Data residency | French supervisors and the bank's own policy expect customer data, prompts included, to stay in the EU and ideally in France. A service that runs elsewhere needs written sign-off from compliance. | Pin each service to a region and record what can't run in `europe-west9`. Early evidence: no current Gemini model, Agent Runtime or session store runs there, the last model processing in France retired in October 2026, and Runtime can't use CMEK on `eu` ([F3](findings.md#f3-gemini-models-and-europe-west9), [F4](findings.md#f4-ml-processing-inside-france), [F5](findings.md#f5-agent-services-and-europe-west9), [F6](findings.md#f6-cmek-and-the-eu-endpoint)). The trade-off goes to ADR 0004. | 2 | to assess |
| Legal constraints | The agent falls under GDPR, the bank's outsourcing and ICT third-party rules under DORA, and the EU AI Act, which needs the use case classified before go-live. Questions and answers are personal data when staff mention customers. | An audit trail of every question and answer, kept for the 90 days the retention policy sets; a written mapping of the use case against GDPR, DORA and the AI Act in the go-live write-up. | 2, 4 | to assess |
| Answer quality and refusals | A wrong deadline in a complaints answer becomes a regulatory breach. Staff need answers that cite the procedure, and a plain "I don't know" when the documents don't cover the question. | Phase 0 tests the wiring with the stub model only. From phase 2, a fixed set of questions on the four documents, run against Gemini, scored on correct figures, citations and refusals; guardrails on inputs and outputs. | 0, 2 | to assess |
| Latency and cost | Advisers often ask while a customer waits on the phone, so a slow answer is no answer. Finance wants a cost per question before approving a rollout to every branch. | Once Gemini is called, measure median and 95th percentile response time and tokens per question on the `eu` endpoint, then build a monthly cost estimate for a given number of staff. | 2, 4 | to assess |
| Who runs it after go-live | Someone has to own the agent, answer for it to the regulator, and upgrade it when a model retires: `gemini-2.5-flash` retired 20 October 2026 ([F4](findings.md#f4-ml-processing-inside-france)). | A run book, a model upgrade path tested against the question set, and the engagement request for the Forward Deployed Engineering team, stating what the bank runs itself and what it needs help with. | 4 | to assess |

## How the phases feed it

Phase 0 can't move any row past "to assess" on its own: it proves the agent's structure and the offline tests, not behaviour on Gemini. Phase 1 brings evidence for identity and connectors, phase 2 for residency, legal controls, quality and the first latency numbers, and phase 4 turns the table into the go-live recommendation.
